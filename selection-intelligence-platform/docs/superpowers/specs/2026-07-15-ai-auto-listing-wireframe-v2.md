# AI自动刊登系统页面线框说明 v2

## 1. 文档信息

- 文档名称：AI自动刊登系统页面线框说明 v2
- 文档定位：MVP阶段线框级页面说明
- 使用对象：产品、业务、设计、前端
- 版本日期：2026-07-15
- 风格基线：Semi / 飞书式企业后台风格
- 关联文档：`AI自动刊登系统设计文档 v1`

## 2. 文档目标

本文件用于在 `AI自动刊登系统设计文档 v1` 的基础上，进一步明确页面骨架、区域划分、关键入口与模块关系，帮助产品、业务、设计和前端快速对齐页面长相与信息摆放方式。

本文件聚焦线框级说明，目标是回答以下问题：

1. 每个页面由哪些主要区域组成。
2. 各区域的上下左右关系如何组织。
3. 关键操作按钮放在哪里更合理。
4. 不同角色在同一页面上看到的差异是什么。
5. 页面之间如何完成核心业务流转。

本文件不展开视觉细节，也不细化到完整交互稿级别。

## 3. 全局布局基线

### 3.1 整体布局风格

系统整体采用 `Semi / 飞书式企业后台` 参考方向，页面结构强调规整、清晰和高效，避免复杂装饰。整体建议采用：

1. 浅色背景。
2. 白色内容卡片或白色内容容器。
3. 明确的内容边界和分组。
4. 中高信息密度。
5. 统一的状态标签、按钮与表单控件样式。

### 3.2 页面通用结构

除登录页外，后台页面建议统一采用如下结构：

1. 左侧主导航
2. 顶部信息区
3. 页面标题与面包屑区
4. 主内容区
5. 页内固定操作区或底部操作区

标准层级如下：

`左侧主导航`
`顶部信息区`
`页面标题区`
`筛选 / 概览 / 表单 / 工作区`
`底部操作区`

### 3.3 左侧导航规则

左侧主导航建议固定在页面左侧，包含：

1. 顶部：Logo + 系统名称
2. 中部：页面导航入口
3. 底部：当前基线说明或辅助说明卡片

页面导航建议按如下顺序展示：

1. 任务列表
2. 新建任务
3. AI审核页
4. 任务详情
5. 用户管理

为避免信息重复，页面顶部不再放置 `刊登任务 / 用户管理` 这类全局导航按钮。

### 3.4 区块样式规则

页面中的内容建议按模块分卡片或分区展示，避免所有信息直接平铺。常见区块类型如下：

1. 筛选区
2. 操作区
3. 数据表格区
4. 表单区
5. 图片工作区
6. 审核记录区
7. 推送记录区

每个区块需具备：

1. 清晰标题
2. 合理留白
3. 操作归属明确
4. 内容边界明显

### 3.5 按钮层级规则

建议统一按钮层级，便于评审时形成共识：

1. 主按钮：当前页面最重要动作，如 `新建刊登任务`、`保存并发起AI生成`、`提交美国团队审核`
2. 次按钮：辅助动作，如 `重置`、`取消`
3. 风险按钮：`驳回`、`删除`
4. 弱操作入口：`查看`、`编辑`、`重试`

### 3.6 状态表达规则

状态建议使用标签或轻量色块表达，重点状态包括：

1. AI生成状态
2. 审核状态
3. 推送状态
4. 账号状态

颜色使用建议：

1. 处理中：蓝色或中性强调色
2. 成功 / 已完成：绿色
3. 待处理：灰蓝或中性色
4. 失败 / 驳回：红色

## 4. 页面线框说明

### 4.1 刊登任务列表页

#### 页面目标

作为系统主工作台，承接任务检索、查看状态、进入处理、发起新任务等高频操作。

#### 页面线框结构

建议采用以下自上而下结构：

1. 左侧主导航
2. 顶部信息区
3. 页面标题区
4. 筛选区
5. 操作区
6. 列表表格区
7. 分页区

线框关系示意：

```text
+--------------------------------------------------------------+
| 左侧导航：任务列表 / 新建任务 / AI审核页 / 任务详情 / 用户管理 |
+--------------------------------------------------------------+
| 顶部信息区：页面标题 / 页面说明 / 当前用户 / 新建任务按钮     |
+--------------------------------------------------------------+
| 筛选区：品类 | 状态 | 创建人 | 创建时间 | Goods ID / DDID    |
|         [搜索] [重置]                                        |
+--------------------------------------------------------------+
| 操作区：[+ 新建刊登任务]                         共 XX 条记录 |
+--------------------------------------------------------------+
| 表格区                                                        |
| 任务编号 | Goods ID | DDID | AI状态 | 审核状态 | 推送状态    |
| 当前处理人 | 创建人 | 创建时间 | 操作                        |
+--------------------------------------------------------------+
| 分页区                                                1 2 3  |
+--------------------------------------------------------------+
```

#### 区域说明

##### 左侧主导航

1. 提供系统主入口。
2. 按 `任务列表 / 新建任务 / AI审核页 / 任务详情 / 用户管理` 排列。
3. 管理员额外拥有进入 `用户管理` 的权限。

##### 顶部信息区

1. 展示当前页面名称和简短说明。
2. 右侧展示当前用户信息和页面主操作。

##### 页面标题区

1. 标题：`刊登任务`
2. 可加一行简短说明，帮助业务同学快速理解当前页作用。

##### 筛选区

建议为单层横向筛选布局，优先展示最高频条件：

1. 品类
2. 审核状态
3. AI生成状态
4. 创建人
5. 创建时间
6. Goods ID / DDID 搜索框

##### 操作区

1. 左侧主按钮：`+ 新建刊登任务`
2. 右侧展示结果总数

##### 表格区

表格为本页主体，建议字段顺序如下：

1. 任务编号
2. Goods ID
3. DDID
4. 品类
5. AI生成状态
6. 审核状态
7. 盘古推送状态
8. 当前处理人
9. 创建人
10. 创建时间
11. 操作

##### 分页区

位于底部右侧，保持后台标准分页形态。

#### 关键按钮位置

1. `+ 新建刊登任务` 放在表格上方左侧，作为页面唯一主按钮。
2. `查看`、`编辑`、`处理` 放在表格操作列。
3. `搜索`、`重置` 放在筛选区最右侧。

#### 角色差异

##### 上海运营

1. 可看到 `+ 新建刊登任务`
2. 在待自己处理的任务上显示 `编辑/处理`

##### 美国团队

1. 不显示新建按钮
2. 待自己审核的任务显示 `处理`
3. 其他任务以 `查看` 为主

##### 管理员

1. 可查看全部任务
2. 异常任务可增加 `查看异常` 或 `处理异常`

#### 关键状态提示

1. 无数据时展示空状态，并给上海运营提供新建入口。
2. AI生成失败任务行需突出失败状态。
3. 审核驳回任务需在状态上明显可见。

### 4.2 新建任务 / 素材上传页

#### 页面目标

让上海运营快速录入基础信息、上传标准素材包，并发起 AI 生成。

#### 页面线框结构

建议采用以下自上而下结构：

1. 左侧主导航
2. 顶部信息区
3. 面包屑与页面标题区
4. 基础信息表单区
5. 素材上传区
6. 底部操作区

线框关系示意：

```text
+--------------------------------------------------------------+
| 左侧导航                                                      |
+--------------------------------------------------------------+
| 顶部信息区                                                    |
+--------------------------------------------------------------+
| 面包屑：任务列表 > 新建任务                                   |
| 页面标题：新建刊登任务                                        |
+--------------------------------------------------------------+
| 基础信息区                                                    |
| 品类 | 路线类型 | Goods ID | DDID | Base Price | US Price    |
+--------------------------------------------------------------+
| 素材上传区                                                    |
| 全套纸样 [上传]                                               |
| 激光纸样 [上传]                                               |
| 尺码表   [上传]                                               |
| 图片素材 [上传]                                               |
| 工艺备注 [上传]                                               |
+--------------------------------------------------------------+
| 底部操作区： [取消]                    [保存并发起AI生成]     |
+--------------------------------------------------------------+
```

#### 区域说明

##### 面包屑与页面标题区

1. 面包屑帮助用户返回列表页。
2. 页面标题保持直接清晰。

##### 基础信息表单区

建议做成单独卡片，采用两列或三列表单布局，便于提高录入效率。字段如下：

1. 品类
2. 路线类型
3. Goods ID
4. DDID
5. Base Price
6. US Price

上传成功后，系统自动生成并记录 `source_package_path`，不要求用户手工填写。

##### 素材上传区

建议按素材类型纵向排列，每一行代表一类素材，右侧提供上传动作。对于已上传素材，可在同一行展示：

1. 文件名
2. 上传进度
3. 上传成功状态
4. 替换
5. 删除

##### 底部操作区

底部操作区建议固定，避免上传内容较多时用户需要滚动回页面顶部或底部寻找操作按钮。

#### 关键按钮位置

1. 每类素材右侧提供 `上传` 或 `替换`
2. 页面底部右侧主按钮：`保存并发起AI生成`
3. 页面底部左侧次按钮：`取消`

#### 角色差异

本页仅上海运营可见和可操作。

#### 关键状态提示

1. 必填字段缺失时，在字段下方直接提示。
2. 上传失败时，在对应素材行展示错误原因和重试入口。
3. 成功创建任务后，跳转至任务详情或审核页更利于用户连续操作。

### 4.3 AI结果与审核页

#### 页面目标

承接 AI 结果查看、人工修订和双人审核，是整套系统最关键的工作面。

#### 页面线框结构

建议采用 `顶部信息条 + 左图右表单 + 底部操作栏` 的双栏工作区结构。

线框关系示意：

```text
+--------------------------------------------------------------------+
| 左侧导航                                                            |
+--------------------------------------------------------------------+
| 顶部信息区                                                          |
+--------------------------------------------------------------------+
| 面包屑：任务列表 > 任务处理                                         |
| 顶部任务信息条：任务编号 | Goods ID | DDID | 状态 | 当前处理人      |
+--------------------------------------------------------------------+
| 左侧图片区                 | 右侧结构化表单区                      |
| 原始素材预览               | 分组1：价格与基础信息                |
| AI生成图预览               | 分组2：标题与描述                    |
| 图片分类切换               | 分组3：商品属性                      |
| 图片替换/删除/排序         | 分组4：AI提取依据摘要                |
| 已通过数量                 | 分组内字段需覆盖 MVP 文本结果表      |
+--------------------------------------------------------------------+
| 底部操作栏： [保存修改] [驳回] [提交美国团队审核 / 审核通过 / 推送] |
+--------------------------------------------------------------------+
```

#### 区域说明

##### 顶部任务信息条

建议固定在页面上方，始终展示当前处理上下文，至少包含：

1. 任务编号
2. Goods ID
3. DDID
4. 当前状态
5. 当前处理人

##### 左侧图片区

左侧用于“看图”和“管图”，建议宽度明显大于普通侧栏，但小于右侧表单区。主要承载：

1. 原始素材图
2. AI 输出图
3. 正面 / 背面 / 侧面 / 其他切换
4. 图片大图预览
5. 图片替换
6. 图片删除
7. 图片排序
8. 已通过图片数量

##### 右侧结构化表单区

右侧为主编辑区，建议用分组折叠或卡片分组承载以下内容：

1. 价格与基础信息
2. 标题与描述
3. 商品属性
4. AI提取依据摘要

其中字段需覆盖 `MVP` 文本结果表中的关键字段：

1. 价格与基础信息：
   `Goods ID`、`DDID`、`Base Price`、`US Price`
2. 标题与描述：
   `Style Name（中文）`、`Style Name（英文）`、`Description（中文）`、`Description（英文）`
3. 商品属性：
   `Online Color`、`Neckline`、`Silhouette`、`Sleeves`、`Features`、`Back Style`、`Embellishment`、`Fabric`、`main fabric`、`Length`、`Highest Point`、`Lowest Point`、`Boning`、`Padding`、`Rush Production`、`Lining`、`Type of Closure`、`Hook and Eye`、`Online Size`
4. AI提取依据摘要：
   `AI提取依据摘要`

右侧区需要支持长表单滚动，但分组标题需清晰，便于快速定位。

##### 底部操作栏

建议固定在页面底部，随着角色和状态变化显示不同按钮组合。

#### 关键按钮位置

1. `保存修改` 放底部操作栏左侧或中间位置
2. `驳回` 放底部操作栏中间，作为风险操作
3. 主流程按钮放底部操作栏最右侧
4. 图片级操作放在左侧图片区对应图片附近

#### 角色差异

##### 上海运营审核阶段

1. 左侧图片区可编辑
2. 右侧中文字段、价格、基础属性可编辑
3. 底部主按钮为 `提交美国团队审核`

##### 美国团队审核阶段

1. 左侧图片区默认只读
2. 右侧英文相关字段可编辑
3. 底部主按钮为 `审核通过，待推送盘古`

##### 待推送盘古阶段

1. 页面大部分内容切为只读
2. 上海运营可见主按钮 `一键推送盘古`

##### 管理员

1. 默认只读查看
2. 异常状态下可补充重试或异常处理入口

#### 关键状态提示

1. AI生成中时，本页不可进入正常编辑态。
2. AI生成失败时，页面顶部或图片区上方展示失败原因。
3. 驳回时必须弹出原因填写区域。
4. 保存成功后使用轻量提示，不离开当前页。

### 4.4 任务详情页

#### 页面目标

用于查看任务完整结果、审核过程和推送记录，是任务复盘和对外同步的重要入口。

#### 页面线框结构

建议采用 `顶部信息 + 分区详情` 的单列详情页结构。

线框关系示意：

```text
+--------------------------------------------------------------+
| 左侧导航                                                      |
+--------------------------------------------------------------+
| 顶部信息区                                                    |
+--------------------------------------------------------------+
| 面包屑：任务列表 > 任务详情                                   |
| 页面标题：任务编号 + 当前状态标签                             |
+--------------------------------------------------------------+
| 基础信息区                                                    |
+--------------------------------------------------------------+
| 任务状态区                                                    |
+--------------------------------------------------------------+
| 文本结果区                                                    |
+--------------------------------------------------------------+
| 图片结果区                                                    |
+--------------------------------------------------------------+
| 审核记录区                                                    |
+--------------------------------------------------------------+
| 推送记录区                                                    |
+--------------------------------------------------------------+
```

#### 区域说明

##### 基础信息区

展示任务基础属性和关键信息，如：

1. 品类
2. 路线类型
3. Goods ID
4. DDID
5. Base Price
6. US Price
7. 素材包地址
8. 创建人
9. 创建时间

##### 任务状态区

建议补齐任务主表中的流程字段：

1. AI生成状态
2. 审核状态
3. 盘古推送状态
4. 当前处理人

##### 文本结果区

展示最终结构化文本结果，建议完整承接文本结果表中的最终确认字段。

##### 图片结果区

展示最终确认用于刊登的图片结果，支持按图片类型分组查看。

##### 审核记录区

建议使用时间线或表格式记录以下内容：

1. 审核节点
2. 审核人
3. 操作动作
4. 变更摘要
5. 审核意见
6. 时间

##### 推送记录区

记录推送盘古的结果，包括：

1. 推送状态
2. 推送时间
3. 失败原因
4. 重试记录

#### 关键按钮位置

1. 页面顶部可按状态显示 `继续处理`
2. 默认以查看为主，不宜放置过多操作按钮

#### 角色差异

1. 上海运营和美国团队均可查看自己相关任务
2. 管理员可查看全部任务详情
3. 仅在满足状态条件时展示继续处理入口

#### 关键状态提示

1. 驳回记录要完整显示
2. 推送失败记录要可追溯
3. 若尚未生成完整结果，应提示当前处于处理中

### 4.5 用户管理页

#### 页面目标

支持管理员完成账号新增、角色调整和账号启停的基础治理动作。

#### 页面线框结构

建议采用 `标题区 + 操作区 + 用户表格 + 弹窗` 的轻量后台结构。

线框关系示意：

```text
+--------------------------------------------------------------+
| 左侧导航                                                      |
+--------------------------------------------------------------+
| 顶部信息区                                                    |
+--------------------------------------------------------------+
| 页面标题：用户管理                                            |
+--------------------------------------------------------------+
| 操作区：[新增账号]                                            |
+--------------------------------------------------------------+
| 用户表格                                                      |
| 用户名 | 角色 | 状态 | 创建时间 | 更新时间 | 操作            |
+--------------------------------------------------------------+
| 弹窗：新增 / 编辑账号                                         |
+--------------------------------------------------------------+
```

#### 区域说明

##### 页面标题区

标题保持简洁直接，不增加过多说明文字。

##### 操作区

仅保留一个主按钮 `新增账号`，避免页面过重。

##### 用户表格区

用于集中管理账号信息，字段建议为：

1. 用户名
2. 角色
3. 状态
4. 创建时间
5. 更新时间
6. 操作

##### 弹窗区

新增和编辑可通过弹窗完成，字段建议包括：

1. 用户名
2. 角色
3. 状态

#### 关键按钮位置

1. `新增账号` 放表格上方左侧
2. `编辑`、`启用`、`禁用` 放在操作列

#### 角色差异

本页仅管理员可见。

#### 关键状态提示

1. 禁用账号需二次确认
2. 已禁用账号在状态上需明显区分

## 5. 页面间流转关系

### 5.1 主流转

页面主链路建议如下：

`任务列表页 -> 新建任务页 -> AI结果与审核页 -> 任务详情页 -> 返回任务列表页`

### 5.2 典型进入方式

1. 从任务列表点击 `新建刊登任务` 进入新建页
2. 新建成功后进入审核页或详情页
3. 从任务列表点击 `处理` 进入审核页
4. 从任务列表点击 `查看` 进入任务详情页

### 5.3 审核后回流

1. 上海运营提交后，任务回到列表并变为待美国团队审核
2. 美国团队审核通过后，任务回到列表并变为待推送盘古
3. 任一方驳回后，任务回到列表并重新进入上海运营队列

### 5.4 管理后台流转

管理员通过左侧主导航进入用户管理页，处理完成后返回任务列表页。

## 6. 线框建议总结

### 6.1 最重要的页面形态结论

1. 列表页采用标准后台结构：`筛选区 + 操作区 + 表格区`
2. 新建页采用表单分组结构：`基础信息 + 素材上传 + 底部固定操作`
3. 审核页采用双栏工作区结构：`左图右表单 + 底部固定操作`
4. 详情页采用单列分区结构：`结果查看 + 审核记录 + 推送记录`
5. 用户管理页采用轻量治理结构：`操作区 + 表格 + 弹窗`

### 6.2 对设计出稿的建议

后续进入视觉稿阶段时，建议优先产出以下页面：

1. 刊登任务列表页
2. AI结果与审核页
3. 新建任务 / 素材上传页

这三个页面覆盖了本期 MVP 的主要业务价值，也是最值得优先统一设计语言和页面节奏的部分。

### 6.3 对前端落地的建议

后续若进入静态页或前端实现阶段，建议按照以下顺序推进：

1. 先搭建全局后台骨架
2. 再实现列表页
3. 再实现新建页
4. 最后实现审核页和详情页

这样可以最大程度复用同一套导航、表单、表格和状态组件模式。
