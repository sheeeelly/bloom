# Bloom · AT 智能选品工作台（HTML Demo）

基于选品闭环 PRD 的纯静态前端演示，单文件、无依赖，直接用浏览器打开 `index.html` 即可。

## 覆盖的流程

三信号入库 → 机会池 → 选品方案草稿 → AI 审批 → 负责人审批 → 写入选款 → 打版线下

## 页面

| 页面 | 内容 |
|---|---|
| 总览摘要 | KR1–KR4 指标、批次漏斗、五信号源健康度、三类场景分布 |
| 监控报告 | 竞品网站雷达（AT 轨）、**竞品广告投放**、**竞品邮件主推**、社媒舆情、AZ 相似款表现 |
| 机会池 | 销量池（上新×热销靠前）/ 新到池（recency_proxy 隔离）/ 正向改款池 / 负向改款池 |
| 选品方案 | 草稿编辑（场景、改款、规格、BOM 定价、库存可生产性）、Gates 快照、AI 建议（R1–R7 允许集）、状态机流转 |
| 审批队列 | 负责人视角：证据区 + 通过/驳回（原因必填回流） |
| 写入选款回执 | outbox 同步状态、generation_source=system_hub_at、Sync_Failed 重试 |

## 三类业务场景

- **纯新款**：竞品「上新 × 列表/热销靠前」跟款
- **正向改款**：站内热销款为底座，叠加竞品热卖属性
- **负向改款**：VOC 商品问题 / 高退货率 / 社媒翻车驱动的结构修复

## 五个信号源

竞品网站雷达（AT 轨）、竞品广告投放（Meta/TikTok Ad Library）、竞品邮件主推（Newsletter Hero/次推位）、社媒舆情（人工录入）、AZ 相似款历史销量（盘古三维）。

数据均为前端 Mock，交互（生成草稿 → AI 建议 → 提交审批 → 通过/驳回 → 同步回执）可完整走通。
